# 桌面端界面改版：分析与规划（讨论稿）

> 2026-11-11 起草；第一版实现在分支 `ui-redesign`（未合并，待看效果）。范围只包括桌面端宽屏布局和视觉风格。窄屏和 Android 只要求不被改坏。

## 1. 结论

- **不移植开源项目，用现有代码改布局。** 原因见第 3 节：能合法放进 MIT 仓库的项目都基于 Tailwind 4 或 shadcn。我们的协议层和状态层（`store.ts`、`model.ts`）已经处理了几十个坑，换掉它们得不偿失。开源项目只参考交互，借用代码时保留署名。
- **按官方截图（第 2.1 节）改四处：**
  1. 框架反过来：侧栏改成内缩卡片，会话行只留一行。
  2. 标题栏只放 `项目 / 会话 ⌄` 和窗格按钮；统计和状态放进右侧窗格（改动、后台任务、待办、方案、会话信息）。
  3. 输入框的控件行移到框外下方，加用量环。
  4. 消息流里工具调用合并成一行灰字，每轮结束显示用时和 token。
- 配色已经接近官方，只做微调；回复改用无衬线体。
- 终端、浏览器、文件、附件、行内评论这几项先不做，原因是需要新的服务端能力。

## 2. 现状和官方的差距

官方布局的依据：code.claude.com/docs/en/desktop，以及 2026-04 的桌面端重设计公告。现状的依据：开发模式 `/?s=rich` 在 1440×900 下的截图。

| 区域 | 官方 Claude Code 桌面端 | cchub 现状 | 差距 |
|---|---|---|---|
| 左栏 | “+ New”；会话默认按文件夹分组，可按状态、项目过滤；已归档的会话在 View all 里 | “新建会话”；“项目”和“最近”两块；底部有额度条和服务器内存 | “最近”和“项目”大部分内容重复（截图里同样 5 个会话出现了两次）；额度放在左栏底部，离输入框很远；没有过滤 |
| 顶栏 | 会话标题（点击可重命名）加 ▾ 会话菜单；右侧是窗格按钮（改动、任务等）和“显示/隐藏详情栏” | 标题/项目/设备面包屑；右侧依次是“已连接”“设备在线”、“结束会话”、外观、设置 | 全局状态（连接、外观、设置）挤在会话顶栏里；会话操作只有“结束会话” |
| 右侧 | 会话详情栏（session rail）：环境、改动 `+12 −1`、上下文百分比、后台工作；点开后是对应窗格 | 没有。待办在消息流顶部，后台任务是弹窗 | **差距最大**。统计信息没有固定的位置 |
| 消息流 | 三档视图（普通/思考/详细，Ctrl+O 切换）；工具调用折叠成摘要 | 工具调用逐条显示成一行，思考折叠显示；被拦截的命令用大块红色卡片 | 没有视图档位；连续的工具调用不合并；报错太抢眼 |
| 输入框 | 左边是“+”；下方一行从左到右是环境、项目文件夹、权限模式、模型、用量环 | 下方一行是“上下文 244k”文字、模型、发送按钮 | 缺权限模式显示和用量环；上下文只是一行文字 |
| 统计 | 用量环（点开看套餐额度）、详情栏里的 Context 卡片和 Changes 卡片 | 额度在左栏底部，上下文在输入框里，上一轮用时在状态行 | 统计分散在三处，缺本会话的改动行数和累计用时 |
| 风格 | 米色底加赤陶色强调，标题用衬线体，界面用无衬线体；边框细，阴影少 | 色值已经接近；回复正文默认衬线体；工具行用等宽字体，在 Windows 上回退成难看的中文字体（截图里很明显） | 等宽字体的回退链要修；整体可以更紧凑、阴影更少 |

## 2.1 官方截图观察（2026-11-11 补充）

来源：
- 官方演示视频的缩略图和分镜。
- 官方产品页、文章配图。
- 一篇日文实操文章里的 Windows 版截图（2026-05，Claude 桌面端浅色）。

参考图存在 `.cc/ref/`，不提交，版权不属于本项目。最有用的几张：
- `z42`：Code 会话页加窗格菜单。
- `z10`：新会话页加用量统计。
- `z44`：工具行和本轮统计。
- `z45`：Files 窗格。
- `z25` / `z26` / `z27`：侧栏的过滤、分组和行菜单。
- `z38` / `z39`：权限模式菜单和“+”菜单。
- `o08`：diff。
- `video-thumb`：深色版多窗格。

看不到的：
- 深色主题的完整 Code 页。
- Edit / Bash 展开后的样式、审批、待办、思考块。
- Diff、Terminal、Tasks 三个窗格的内部样式。

和第 2 节推测不同、需要据此修正的地方：

| 区域 | 官方实际样子 |

| 会话标题栏 | `项目 / 会话名 ⌄`，运行中时图标角上有蓝点。右上只有一个“窗格 ⌄”按钮，点开列出 Preview / Diff / Terminal / Files / Background tasks / Plan，带快捷键 |

| 新会话页 | 问候语，加一张**用量统计卡**：会话数、消息数、总 token、活跃天数、连续天数、高峰时段、常用模型，以及活跃热力图。可切换全部 / 30 天 / 7 天 |
| 配色（目测） | - 底色约 `#FAF9F6`，侧栏卡片约 `#F3F1EC`，选中行约 `#E6E3DC`<br>- 边框约 `#DDD9D0`，几乎没有阴影<br>- 主按钮黑底白字，强调色是橙色（只用于星标和发送键）<br>- Code 页里的用户消息是浅蓝底蓝字 |

## 3. 开源项目评估

调研结果，许可证以仓库 LICENSE 为准：

| 项目 | 许可证 | 技术栈 | 结论 |
|---|---|---|---|
| opcode（原 Claudia） | AGPL-3.0 | Tauri 2、React、Tailwind、Radix、recharts | 不能借代码；风格也不像官方 |
| claudecodeui / CloudCLI | AGPL-3.0 | React、Tailwind、Electron | 不能借代码；偏 IDE 风格 |
| yume | 专有 | Tauri、React | 不能借代码 |
| cdesktop | Apache-2.0 | Rust 后端 + Tailwind 网页（基于 vibe-kanban 的代码结构），桌面版未发布，2026-05 后无更新 | 自称“开源版 Claude Code Desktop”，布局最接近官方 Code 页；只适合参考布局 |
| Nimbalyst（Crystal 改名） | MIT | Electron，活跃 | 偏可视化工作区（Markdown、原型图、看板），不像官方 |
| Pane（runpane） | 未标准化（介绍为 AGPL-3.0） | Electron/终端优先 | 不能借代码 |
| desktop-cc-gui | MIT | Tauri 2、React 18、Tailwind 4 | 技术栈最接近。逻辑可以参考，样式要全部重写 |
| TOKENICODE | Apache-2.0 | Tauri 2、React 19、Tailwind 4 | 同上。借代码时要保留 NOTICE |
| Crystal | MIT | Electron、Tailwind、Monaco | 已停更；多会话加 diff 的布局可以参考 |
| sugyan/claude-code-webui | MIT | React、Vite | 已归档，太简单 |
| assistant-ui 的 Claude 示例 | MIT | headless 加 Tailwind | 仿的是 claude.ai 聊天界面，不是 Code 的布局 |
| vibe-kanban / companion | Apache-2.0 / MIT | — | 前者已关停，后者已转向，不看 |

没有一个项目复刻了官方“详情栏加窗格”的结构，所以拿过来改并不比自己写省事，还会引入 Tailwind（违反“不引入大型 UI 框架”这条约束）、增加内存。决定：照着官方文档的结构自己实现，样式全部用现有 CSS 变量。

## 4. 目标布局（按官方截图修正）

```
┌─────────────────┐
│ + 新建会话       │  demo-api / 整理认证测试 ⌄                    [▣ ⌄]
│                 │ ─                                              │ 窗格菜单：
│ demo-api    ⚲   │ ─  帮我修一下登录接口……                         │ 改动 / 后台任务
│  ● 修登录接口    │ ━  用了 5 个工具 ›                              │ 待办 / 方案 / 会话信息
│  ◌ 整理认证测试  │    回复正文（无衬线）……                         │
│  ○ 跑一个长任务  │    ┌ 需要审批 ──────────────┐                   │
│ docs-site       │    └────────────────────────┘                   │
│  ○ ……           │    ✱ 2m 14s · 1.7k tokens                       │
│                 │   ┌──────────────────────────────────────────┐ │
│ ● 已连接 · 412MB │   │ 继续补充                               ↵ │ │
│ ⚙ 设置          │   └──────────────────────────────────────────┘ │
└─────────────────┘    自动  +                Sonnet 5.5 · 高  ◔
```

### 4.1 整体框架

- 改成官方结构：侧栏是内缩的圆角卡片，主区域铺在底色上，不再是卡片。
- 窗格从右侧打开，最多同时开一个。窗格打开时对话区变窄。

### 4.2 侧栏

- 顶部只有“新建会话”。不做 Chat / Cowork 切换，也不做 Routines 等导航项。
- 会话按项目分组。组标题是灰色小字，右侧是过滤按钮。过滤按钮打开一个菜单：
  - 状态：全部 / 等你决定 / 运行中。
  - 分组：按项目 / 按时间。
- 去掉“最近”这一块：按时间分组已经覆盖了它。
- 会话行改成一行：状态点加标题。
  - 状态点：等你决定是强调色，正在运行转圈，空闲是绿点，已结束是空心灰圈。
  - 取消第二行的状态文字。正在做什么，改到鼠标悬停提示和会话标题栏里显示。
  - 悬停时出现 ⋮ 菜单，里面有结束会话、关闭会话、复制恢复命令；以后再加重命名、置顶。
- 底部：连接状态和服务器内存一行，下面是“设置”（连接和外观合并到一处）。额度移到输入框旁边的用量环。

### 4.3 会话标题栏

- 左边：`项目 / 会话名 ⌄`，下拉菜单和侧栏的 ⋮ 菜单内容相同。正在运行时标题前有状态点。
- 右边：“窗格 ⌄”按钮，列出：
  - 改动（本会话 Edit / Write 的 diff 汇总）
  - 后台任务（替代现在的弹窗）
  - 待办
  - 方案（最近一次 ExitPlanMode 的方案）
  - 会话信息（环境、上下文、本会话统计）
- 设备离线、断线仍然用提示条。

### 4.4 窗格（替代第一版设想的“详情栏”）

官方截图里能确认的是“窗格菜单 + 右侧窗格”这套结构，详情栏只在文档里出现过。我们先做窗格，内容和原来设想的卡片相同：

| 窗格 | 内容 | 数据来源 |
|---|---|---|
| 改动 | 按文件分组的 diff，参考 `o08`：文件头显示路径和 `+N −M`，双列行号，整行红底绿底 | 汇总 Edit / MultiEdit / Write 工具的输入；注明不含 Bash 产生的改动 |
| 后台任务 | 列表加输出，展开某一项时才请求输出 | `thread.tasks`、`read_task_output` |
| 待办 | 原地更新的清单 | `thread.todos` |
| 方案 | 最近一次方案的 Markdown | 方案确认请求里的 `plan` |
| 会话信息 | 环境（设备、路径、在线、进程状态）；上下文的环和数字；本会话轮数、累计用时、累计 token | `describeCwd`、`thread.context`；在 `model.ts` 里累计 `result` |

- 窄屏下：窗格改成全屏浮层；待办和后台任务入口保持现在的位置，不影响 Android。

### 4.5 输入区

- 输入框改成扁平圆角框，右下角显示 ↵；运行中显示方形停止键。
- **控件行移到输入框外面下方**：
  - 左边：权限模式（第一版只显示“自动”）。
  - 右边：`模型 · 强度`（沿用现有菜单）和用量环。用量环点开后显示 5 小时额度、本周额度、上下文、服务器内存。
- 新会话页的输入框上方放项目 chip（现在的“选择工作区”）。
- 现在的状态行（正在运行… · 15s）保留在输入框上方，字号更小。

### 4.6 消息流

- 回复默认用无衬线体，和官方一致；外观面板里仍然可以切换成衬线体。
- 工具调用：连续的工具合并成一行灰字“用了 N 个工具 ›”。
  - 正在运行时显示“正在运行 pytest…”。
  - 有失败时这一行变红。
  - 展开后才逐条显示，Edit 的 diff 也在展开后才出现。
- 详细档（Ctrl+O）：默认把工具全部展开。
- 每轮结束加一行小字：`✱ 2m 14s · 1.7k tokens`。用我们自己的符号，不用 Claude 的星形标志。
- 左边缘加按轮次导航的短横线（可选，放到最后做）。
- 被拦截的命令改成工具行变红，不再用大块红色卡片。
- 用户消息：官方 Code 页是浅蓝底。我们保留现在的灰底气泡，还是改成浅蓝底，待定。
- 审批、提问、方案卡片永远不合并、不折叠。

### 4.7 新会话页

- 问候语 + 输入框，参考 `z10`。
- 可选：用量统计卡。只用客户端已有的数据：会话数、活跃天数（来自会话列表的时间）、当前额度。官方卡片里的总 token 和热力图需要 `hubd` 统计 `.jsonl`，会突破“只解析信封”的约束，这一版不做。

### 4.8 视觉

- 颜色按第 2.1 节的目测值微调浅色主题。深色主题用演示视频的缩略图作参考。另外五套配色保留。
- 少用阴影，统一 1px 边框。
- 圆角：输入框和卡片 12px，按钮和 chip 6～8px，弹窗 14～16px。
- 加间距、圆角、字号变量，替换散落在各处的数值。
- 修等宽字体的回退链：中文字体放最后。
- 不用 Anthropic 的 logo、字体、星形标志、吉祥物。

## 5. 不做（这一版）

终端窗格、浏览器预览、文件树、附件和拖拽、diff 行内评论、分屏、PR/CI 状态、权限模式切换、基于 git 的改动统计。这些都要新的 `hubd` 能力或协议。以后单独立项。

## 6. 分步计划

每一步做完，都在 1440×900、1200×800、900×460 三种窗口和窄屏下截图检查，同时跑 `npm test`。

| 步骤 | 内容 | 主要文件 | 验收 |
|---|---|---|---|
| 0 拆文件 | 不改行为，把 `App.tsx` 拆成 `Sidebar.tsx`、`TopBar.tsx`、`Composer.tsx` | `App.tsx` | 截图和改动前逐像素一致；`npm test` 通过 |
| 1 框架和视觉 | 侧栏改成内缩卡片，主区域铺底色；加间距、圆角、字号变量；修等宽字体；回复默认无衬线体 | `styles.css`、`appearance.ts` | 六套配色截图无错位 |
| 2 侧栏和标题栏 | 单行会话行、过滤和分组菜单、去掉“最近”、⋮ 菜单、底部状态和设置入口；标题栏改成 `项目 / 会话 ⌄` 加窗格按钮 | `Sidebar.tsx`、`TopBar.tsx`、`sidebar.ts`、`Dialogs.tsx` | `sidebar.test.ts` 加过滤和分组用例；等你决定的会话在任何过滤下都能看到 |
| 3 输入区 | 扁平输入框，控件行移到下方，权限模式显示，用量环和浮层；新会话页加项目 chip | `Composer.tsx`、`Dialogs.tsx` | 900×460 下浮层不被裁（用 `useMenuFit`） |
| 4 消息流 | 合并成“用了 N 个工具”、Ctrl+O 详细档、每轮统计行、报错改成行内显示 | `Thread.tsx`、`model.ts` | `model.test.ts` 覆盖合并规则；审批、提问、方案卡片不被合并 |
| 5 窗格 | 改动、后台任务（替代弹窗）、待办、方案、会话信息 | 新增 `Panes.tsx`；`model.ts` 汇总改动、累计统计 | `model.test.ts` 覆盖改动汇总；`/?scene=tasks` 不溢出；窄屏下入口仍在 |
| 6 收尾 | 新会话页统计卡（可选）、轮次导航（可选）；实测窗口空闲内存不高于改版前；更新 `AGENTS.md` 项目地图和 `DESIGN.md` 第 7 节 | — | 内存对比写进提交信息 |

风险：

- `App.tsx` 有 549 行，要先拆分文件再改，否则改动很难审查。
- 窗格会增加 DOM。后台任务的输出只在展开时才请求。
- 卡片内容只在数据变化时重算，避免长会话卡顿。
